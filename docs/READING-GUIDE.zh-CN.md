# 阅读、AI 与采集状态使用说明

这次更新补上了从“看到新闻”到“保存、跟进、检查是否更新”的阅读流程，同时修复定稿、论文归期、首次启动和邮件确认中的问题。原有透明评分不变，个性化阅读操作只影响你的浏览器视图。

## 每天如何阅读

- **今日概览**汇集当前榜单里的内容，方便先浏览再打开详情。它属于已有榜单的展示，不会替代来源事实核查，也不代表已经由大模型审核。
- **事件跟进**区分新事件、已有事件的新变化和看过的覆盖。标记“已看”后，变化比较以本设备的阅读记录为准；多个来源讨论同一件事，也可能只是重复引用同一消息。
- **阅读库**集中保存收藏和稍后读，可以标记已读。首页支持全部、未读、关注等阅读筛选；“兴趣”设置可按关键词、公司或项目关注，也可隐藏不想看的内容。这些规则不会改动公开榜单的分数和名次。
- **搜索**同时检索归档与当前实时榜单，重复实体合并展示，并注明来源范围。归档只是已经发布的保留窗口；搜索结果不等于整个互联网的实时新闻。
- **采集与投递状态**在 `#/status`：查看数据是否更新、哪些来源失败或降级、定稿还缺哪些来源、邮件服务商实际接受了多少收件人。技术日志默认收起。

阅读记录和偏好保存在当前设备的浏览器里。设置备份只包含选定的兴趣规则，不会带出阅读历史或收藏的文章文本；清理浏览器站点数据会清除本地阅读记录。

## “最新发布”和“刚刚抓取”是两件事

网站每次重新生成时，发布时间可能更新；新闻源的实际读取时间可能更早。首页和状态页分别展示这两个时间，不会因为重建静态网页就把旧新闻说成刚抓到。默认采集计划约每三小时运行，GitHub 可能延迟；状态页的下次时间是按仓库默认计划推算的估计值，自定义计划应以自己的工作流为准。

一期仍按 `config.yaml` 的时区和截止时间切日，默认美西自然日。实时一期结束后，如果网站还没完成下一次采集，会显示“已截止，等待更新”，不继续把它当作正在更新的一期。

首次安装时，一些历史数据无法补造，例如之前每天的 GitHub 星标读数。网站会显示“历史仍在积累”和缺少的历史榜单。只有实时一期时，首页也能直接使用；第一期关闭后才开始形成归档。

定稿现在按来源分别记录。一个来源失败不会因为另一个来源成功而永久封存错误或过早的互动数；后续运行可补上仍在获取窗口里的来源，已经完成的来源保留当时读数。超过来源历史窗口仍无法恢复的数据会继续标成未完成，不会伪装为已成功重读。已有官方公告的历史指标也不会被几天后的点赞数反向覆盖。

## 三类接口分别做什么

| 接口或配置 | 作用 | 放在哪里 | 没有 Key 时 |
|---|---|---|---|
| 流水线 LLM API | 为新闻生成翻译、简介、值得关注的原因、每日与每周要点 | 仓库 Actions secrets：`RESONANCE_LLM_API_KEY`，可选 `_BASE_URL`、`_MODEL`；内容语言由 `config.yaml` 的 `enrich.languages` 决定 | 继续抓取、评分和发布原文；不新生成翻译与要点 |
| 浏览器 AI API | 点击条目后，按你的模型生成“值不值得看”等临时总结 | 网站“模型”和“凭据”设置 | 普通阅读、搜索归档、收藏和导出仍可用；不发起需要 Key 的模型请求 |
| 网站静态 JSON API | 向网页、报告、MCP 等提供已发布数据，例如 `manifest.json`、`latest.json` | 网站 `/api/v1/` | 公开读取不需要模型 Key |

**浏览器里填写模型 Key，不会自动配置 GitHub Actions。** 流水线 Key 也不会下发到网页，更不会替访问者支付浏览器总结的费用。搜索服务 Key、X 服务 Key 和邮件凭据各有独立用途，应配置到对应功能。

默认流水线语言是 `[en, zh]`，有可用的流水线 Key 时会请求中英双语内容。没有 Key 时不进行新的 LLM 调用；如果此前已有适配当前条目的翻译或要点缓存，仍可继续展示。条目未翻译时保留原文，页面切成中文并不意味着所有新闻已自动翻译。首次只有实时一期时，流水线通常要等有关闭的一期后才生成每日和每周要点。

## 总结语言的三种选择

1. **跟随界面（自动）**：在模型设置里选“跟随界面语言”。打开总结时，以当前中文或英文界面作为初始输出语言。
2. **固定语言**：在模型设置里明确选中文或英文。之后打开总结都从这个默认语言开始，不再跟随界面。
3. **本次覆盖**：总结面板内的语言选项只调整这一次总结；不会默默改掉全局默认设置。缓存按语言、模型等条件区分。

上述三项控制的是你在浏览器发起的总结。每天自动发布的翻译和日报、周报语言仍由流水线配置决定。

## 邮件结果如何判断

状态页的“已接受”表示邮件服务商已接受请求，不保证已经落入收件箱，也不排除后续退信。若只接受部分收件人，界面显示部分成功及成功/失败数量；后续重试只处理尚未完成的收件人，已确认接受的地址不会跟着重复发送。页面不会显示内部收件人指纹或地址。

新配置默认每周二当地 08:30 投递，设置页显示下次计划时间及报告覆盖日期；已有用户计划不会自动迁移。手动测试失败、配置错误或没有可发的一期，都不能再显示成“邮件已发送”。具体状态字段、兼容性和操作注意事项见 [邮件可靠性变更](./DELIVERY-CHANGES.md)。

浏览器设置页仍需保存配置才能改变仓库的投递计划；状态页的工作流链接仅用于查看运行记录，不会自动触发采集或发送邮件。
